## v0.7.25 published — 2026-10-01

[v0.7.25](https://github.com/freefrank/LostOdysseyRecomp/releases/tag/v0.7.25) was published at 2026-10-01T08:04:23Z. It is not a draft or pre-release and is now the latest release. It was cut from annotated tag `v0.7.25` on commit `2c65f0b57b2111d5d90334a2a1a06f3ff46dc27b` (`docs: prepare v0.7.25 release notes`; the preceding commit `bb18943` bumped the CMake source version to 0.7.25). The release notes are the matching [Changelog](../CHANGELOG.md#v0725--2026-10-01) section. The three packages are listed under [Published v0.7.25 assets](#published-v0725-assets); no separate `portable_dx12.lospd` was attached.

This is the first release built and published by Gitea Actions (PR #115, merged 2026-10-01 as `e3ad1b9`). The `release.yml` run, [Gitea run 67](https://git.zkx.ca/freefrank/LostOdysseyRecomp/actions/runs/67), started when the tag was pushed to `zkx` after GitHub, and all five jobs succeeded: create draft 0.2 min, FSR inputs 1.9 min, Windows build and ZIP 8.8 min (`win-t640`), Linux AppImage and Flatpak 13.6 min (privileged docker runner) and publish 2.9 min. About 19 minutes passed from the tag push to publication. It was also the first real GitHub write (draft creation, asset upload, verification and publication) through `LO_GITHUB_TOKEN`; earlier Gitea release runs were build-only or the read-only v0.7.20 rehearsal (run 55). Details and runner setup are in the [Gitea note](notes/ci-gitea.md#releases).

Scope of this record: publication, asset integrity and workflow results only. The release contains the changes in the Changelog entry (the experimental Apple Silicon macOS source path without a package, SHA-256 manifest values in Windows ZIPs (#105), the F1 Force RB Party Switch button (#74), the #102 sky jitter fix with a flicker-suspect log, the project-review runtime hardening (PR #109) and the Flatpak update notice). Their validation is what the [delivered-behavior table](#delivered-behavior-and-validation-scope) records for the merged changes; no new game run was made for the release. The maintainer has not accepted v0.7.25. The 2026-09-29 acceptance of v0.7.15 does not extend to it.

Update, 2026-10-02: two defects in the published v0.7.25 packages came to light after publication. Their fixes are merged on `main` and are in no published package. The Vulkan shader pack inside the packages was built for shader translator version 24 while the v0.7.25 runtime uses 26, so the game rejects it and the first launch compiles all 28,549 shaders (180 s with 15 workers on a 16-thread CPU); PR #127 fixes this ([pack reference](PORTABLE_SHADER_PACK.md#runtime-contract-and-release-check-after-v0725)). In the Linux AppImage and Flatpak, DLSS was reported unavailable on an NVIDIA GPU ([#116](https://github.com/freefrank/LostOdysseyRecomp/issues/116)): the game looked for NVIDIA's library in its working directory and packaging had rewritten that library, which breaks its signature; PR #120 fixes this. Neither finding changes the publication, asset or workflow facts recorded above.

## macOS integration branch — 2026-10-01

The integration combines MikeRavenelle's `arm64-macos` work from commit
`b7951cd` with `main` commit `ca0d8fa`; the local integration validation uses
commit `e7b45b6`. It remains experimental and has no public Mac release.
The changes cover Apple Silicon memory and threading, Metal/MetalFX, packaging
and test workflow support. The integration also includes the independent shader
predicate, constant-cache, DLC hashing and updater identity fixes recorded in
the current branch.

Recorded local checks include a complete Windows clang-cl runtime build and link
with D3D12/Vulkan/DLSS/FSR/FG enabled, nine focused Windows test targets, and a
complete ARM64 Mac runtime build and link with eight focused Mac test targets.
The Windows production-build receipt is `fffbd56`; the final Mac validation
source tree is `fe7131f` (the later changes select pinned zstd on Mac and adjust
focused test staging/diagnostics without changing Windows runtime behavior).
The Mac build also passes the pinned-zstd portable-shader-pack checks after
matching zstd to the deployment target. On an M1 Max with 32 GiB running macOS
26.6.2, cold `--prepare-shaders-only` compiled 28,484 shaders with zero failures
and exited successfully in about 319 seconds. The 300-second new-game/first-battle
script passed in 302.2 seconds including shutdown (`passed=true`,
`unfinished_steps=0`, zero error lines, no crash reports). Four 1280×720 captures
show the opening, battle menu, attack and return to the menu. Local evidence is
retained under `out/macos-integration/mac-validation/` (`result.json`,
`runtime.log` and the captures).
This is not long-play, broad-scene, image-quality or performance acceptance;
the mixed cutscene/battle frame window is not a standalone benchmark. The
branch remains an experimental source integration. The local ad-hoc package was
signature-checked; an installed app reused the shader cache with 28,504 valid,
zero missing/invalid shaders and zero DXC attempts. This is cache-reuse evidence
and adds no new gameplay coverage.

Update, 2026-10-01: the integration was merged into `main` as `e7b45b6` and is
part of the [v0.7.25](#v0725-published--2026-10-01) source, as an experimental
Apple Silicon source-build path. v0.7.25 publishes no macOS package, and the
validation above is unchanged. The text above keeps its original wording as the
record of that integration.
